# IAP_CONTR 软件复位机制详解

> 来源：AI8051U 官方手册第 291、318-319 页

---

## 1. 快速回答

```c
IAP_CONTR = 0x60;  // 这一行执行后...
// ...CPU 会立即开始复位流程，但需要几个时钟周期完成
// 之后代码通常不会执行到这里了
```

**这是一次完整的 CPU 复位**，不是"暂停跳转"。相当于给芯片按了一次复位键，只是复位后跳到了 ISP 区而不是用户区。

---

## 2. 机制详解

### 2.1 `0x60` 是两位的组合

```
IAP_CONTR (地址 0xC7)

位    B7      B6      B5      B4      B3      B2      B1      B0
名    IAPEN   SWBS    SWRST   CMD_FAIL        SWBS2

0x60 = 0 1 1 0 0 0 0 0
         │   │
         │   └── SWRST=1: 触发软件复位
         └────── SWBS=1:  复位后进入 ISP 监控程序区
```

| 位 | 含义 |
|-----|------|
| **SWRST** (B5) | 写 1 触发软件复位——CPU 重新启动 |
| **SWBS** (B6) | 0=复位到用户区，**1=复位到 ISP 监控程序区** |

### 2.2 手册原文（第 318 页）

> "当向 IAP_CONTR 寄存器写入 **0x20** 时，CPU 复位后重新执行用户代码；当向 IAP_CONTR 寄存器写入 **0x60** 时，CPU 复位后复位到 ISP 区执行 ISP 系统代码。"

### 2.3 时序过程

```
┌──────────────────────────────────────────────────────┐
│                                                       │
│  用户代码运行中...                                     │
│      │                                                │
│      ▼                                                │
│  IAP_CONTR = 0x60;   ← 写寄存器                       │
│      │                                                │
│      │  ┌──────────── 注意 ────────────┐              │
│      │  │ 复位不是立即发生的！           │              │
│      │  │ 通常需要等待 2~3 个时钟周期   │              │
│      │  │ 之后代码仍可能执行几条指令     │              │
│      │  └─────────────────────────────┘              │
│      │                                                │
│      ▼ (几个时钟周期后)                                │
│  ┌─────────────────────┐                             │
│  │  CPU 复位            │  相当于按了硬件复位键        │
│  │  • PC = 0x0000       │                             │
│  │  • 寄存器恢复默认     │                             │
│  │  • 因为 SWBS=1       │                             │
│  │    跳转 ISP 监控程序  │                             │
│  └─────────────────────┘                             │
│      │                                                │
│      ▼                                                │
│  系统 ISP 监控程序启动                                 │
│  (相当于冷启动，只是不停电)                             │
│      │                                                │
│      ▼                                                │
│  检测下载命令流 → 烧录 or 跳回用户程序                  │
│                                                       │
└──────────────────────────────────────────────────────┘
```

---

## 3. 不是"暂停跳转"，是"重启"

| 误解 | 实际 |
|------|------|
| ❌ 写入 0x60 就暂停当前程序，跳到 ISP 函数 | ✅ 触发了**完整的 CPU 复位**——寄存器全部重置，PC 回到 0x0000，然后从 ISP 监控程序区开始执行 |

和你按下复位键的效果一模一样，区别只是：
- 复位键 = 复位到用户区
- `0x60` = 复位到 ISP 区

---

## 4. 一个重要的坑 ⚠️

因为复位需要几个时钟周期才生效，`IAP_CONTR = 0x60;` 之后的代码**可能还会执行 1~3 条指令**！

```c
IAP_CONTR = 0x60;    // 触发复位
P0 = 0x00;           // ⚠️ 这条可能被执行！
P1 = 0xFF;           // ⚠️ 这条也可能被执行！
// ... 2~3 个周期后 CPU 才真正复位
```

**正确的做法**：写入后放几个 `_nop_()` 等它生效：

```c
IAP_CONTR = 0x60;    // 触发复位到 ISP
_nop_();             // 等复位生效
_nop_();
_nop_();
while(1);            // 如果复位没生效（异常情况），停在这里
```

---

## 5. 两种复位对比

| | `IAP_CONTR = 0x20` | `IAP_CONTR = 0x60` |
|------|---------------------|---------------------|
| SWRST | 1 (复位) | 1 (复位) |
| SWBS | 0 | **1** |
| 复位后 | 运行用户程序 | 运行 **ISP 监控程序** |
| 效果 | 相当于看门狗复位 | 相当于冷启动进入下载模式 |
| 用途 | 程序重启 | **进入烧录模式** |

---

## 6. 总结

| 问题 | 答案 |
|------|------|
| 是立即生效吗？ | 几乎是——写寄存器后 2~3 个时钟周期内 CPU 复位 |
| 是暂停还是重启？ | **完整重启**——PC 归零，寄存器清零，重新从 0x0000 开始 |
| 0x60 和硬件复位的区别？ | 效果一样，只是 0x60 可以**选择**跳用户区还是 ISP 区 |
| 执行后代码还会跑吗？ | 会跑 1~3 条指令，之后 CPU 复位 |
| 需要加 _nop_() 吗？ | ✅ 建议加 3 个，然后 `while(1)` 兜底 |

---

*💕 一句话：`IAP_CONTR = 0x60` 就是 "按一下复位键，但复位后不给跑用户程序，而是进入 ISP 烧录模式"。是真正的硬件复位，不是软件跳转！*
