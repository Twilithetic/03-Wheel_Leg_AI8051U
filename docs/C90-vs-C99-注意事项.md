## 🔑 C90 vs C99 核心区别速查表

| 序号 | 特性 | C90 (ANSI C) | C99 | Keil C51 |
|------|------|-------------|-----|----------|
| 1 | 变量声明位置 | ⚠️ 必须放在 block 开头 | ✅ 可与语句混排 | ❌ 只能放开头 |
| 2 | `for` 循环内声明 | ❌ `for(i=0;...` 先声明 i | ✅ `for(int i=0;...` | ❌ 不支持 |
| 3 | `//` 单行注释 | ❌ 标准不支持 | ✅ 支持 | ✅ 扩展支持 |
| 4 | `stdint.h` (uint8_t 等) | ❌ 没有 | ✅ 有 | ❌ 需自建(已建) |
| 5 | `stdbool.h` (bool/true/false) | ❌ 没有 | ✅ 有 `_Bool` | ❌ 需自建 |
| 6 | `long long` (64位整型) | ❌ 没有 | ✅ 有 | ❌ 不支持 |
| 7 | 变长数组 VLA `int arr[n]` | ❌ 不支持 | ✅ 支持 | ❌ 不支持 |
| 8 | `inline` 函数 | ❌ 没有 | ✅ 有 | ❌ 不支持 |
| 9 | 复合字面量 (compound literal) | ❌ 不支持 | ✅ `(struct foo){...}` | ❌ 不支持 |
| 10 | 指定初始化器 (designated init) | ❌ 不支持 | ✅ `.member = value` | ❌ 不支持 |
| 11 | 柔性数组成员 `int arr[]` | ❌ 不支持 | ✅ 支持 | ❌ 不支持 |
| 12 | `restrict` 关键字 | ❌ 没有 | ✅ 有 | ❌ 不支持 |
| 13 | 宏可变参数 `#define F(...)` | ❌ 不支持 | ✅ 支持 | ❌ 不支持 |
| 14 | `__func__` 预定义标识符 | ❌ 没有 | ✅ 有 | ❌ 不支持 |
| 15 | 隐式 int (省略类型) | ✅ 允许 | ❌ 禁止 | ⚠️ 避免使用 |
| 16 | 隐式函数声明 | ✅ 允许 | ❌ 禁止 | ⚠️ 避免使用 |
| 17 | 聚合类型非恒定初始化 | ❌ 必须常量 | ✅ 可用变量 | ❌ 必须常量 |
| 18 | 尾随逗号 (enum 最后) | ❌ 不支持 | ✅ 支持 | ❌ 不支持 |

## ⚠️ C90 (ANSI C) 编程注意事项

### 🔴 规则 1：变量声明必须在 block 最开头

**这是最常见的错误！** C90 要求所有变量声明出现在可执行语句之前。

```c
// ❌ 错误：C90 / Keil C51 不支持的写法
void foo(void)
{
    int a = 1;
    a++;
    int b = 2;     // 错误！声明在语句之后
}

// ✅ 正确：C90 风格
void foo(void)
{
    int a = 1;
    int b;          // 所有声明放在最前面
    a++;
    b = 2;
}
```

**补救技巧**：如果确有需要，可以加一对 `{}` 创建新作用域：

```c
void foo(void)
{
    int a = 1;
    a++;
    {   // 新 block，可以重新开始声明
        int b = 2;
        // ...
    }
}
```

### 🔴 规则 2：`for` 循环变量必须先声明

```c
// ❌ 错误：C99 风格
for (int i = 0; i < 10; i++) { ... }

// ✅ 正确：C90 风格
int i;
for (i = 0; i < 10; i++) { ... }
```

### 🔴 规则 3：隐式 int 和隐式函数声明不要用

虽然 C90 允许，但极其危险，务必避免：

```c
// ❌ 危险：隐式 int
static  sizes = 0;       // 等价于 static int sizes = 0;
foo(register i)          // 等价于 int foo(register int i)

// ❌ 危险：隐式函数声明
bar();                   // 没声明就调用，默认返回 int

// ✅ 正确：显式声明
static int sizes = 0;
int foo(int i);
bar();                   // 必须先声明 bar()
```

### 🔴 规则 4：聚合类型初始化必须用编译期常量

这是嵌入式开发中的大坑：

```c
void foo(int arg)
{
    // ❌ 错误：C90 不允许用变量初始化数组/结构体
    int arr[3] = { 0, arg, 2 };      // 编译错误！

    // ✅ 正确：编译期常量
    int arr[3] = { 0, 1, 2 };

    // ✅ 或者声明后再赋值
    int arr2[3];
    arr2[0] = 0;
    arr2[1] = arg;    // 这样是可以的
    arr2[2] = 2;
}
```

### 🟡 规则 5：没有 `//` 注释（理论上）

严格 C90 只有 `/* */` 注释。但 Keil C51 大多数版本**实际上支持** `//`。  
如果遇到奇怪编译错误，可以试试改用 `/* */`。

```c
// 这个在 Keil C51 一般能用
/* 这个肯定能用 */
```

### 🟡 规则 6：函数空参数要写 `void`

```c
// ⚠️ C90 中两者含义不同
extern int foo();        // 参数个数和类型未知（老式声明）
extern int bar(void);    // 明确无参数

// ✅ 推荐：始终写 void
void my_func(void)
{
    // ...
}
```

### 🟡 规则 7：`const` 变量具有外部链接

```c
// C90: const 变量默认 external linkage
const int MAX = 100;   // 其他文件可见！

// ✅ 明确用 static 限制作用域
static const int MAX = 100;  // 仅本文件可见
```

### 🟢 规则 8：`stdint.h` 不在标准库中

Keil C51 没有 `stdint.h`，但你们的项目已在 `def.h` 中自建了一套：

```c
// 来自 def.h（你们项目已有）
typedef unsigned char  uint8_t;
typedef unsigned int   uint16_t;
typedef unsigned long  uint32_t;
```

## 🛠️ Keil C51 特有的扩展（C90 没有，但 C51 有）

这些是 Keil C51 为 8051 架构做的**编译器扩展**，不是 C 标准的一部分：

| 扩展 | 说明 |
|------|------|
| `bit` | 位变量类型，存储于 8051 的 bit-addressable 区域 |
| `sfr` / `sbit` | 特殊功能寄存器声明 |
| `data` / `idata` / `xdata` / `pdata` / `code` | 内存空间指定 |
| `interrupt` | 中断服务函数声明 |
| `using` | 指定寄存器组 |
| `_at_` | 变量绝对地址定位 |
| `reentrant` | 可重入函数 |
| `small` / `compact` / `large` | 内存模型选择 |

## 📝 快速自查清单

写 Keil C51 代码时，心里默念这几条：

- [ ] 变量声明都在 `{` 之后、语句之前？
- [ ] `for` 循环变量已在外部声明？
- [ ] 数组/结构体初始化用的是常量？
- [ ] 函数空参数写了 `void`？
- [ ] 没有省略类型声明（不写隐式 int）？
- [ ] 所有函数调用前都有声明/头文件？
