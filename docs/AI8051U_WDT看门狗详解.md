# AI8051U WDT（看门狗定时器）完全解析

> **时间**：2026-05-03
> **来源**：AI8051U 手册第 10 章 + 范例程序

---

## 1. 一句话解释

**看门狗就是一个倒计时炸弹——你必须定时"拆弹"（喂狗），否则它爆炸（复位芯片）。**

---

## 2. 为什么要看门狗？

程序可能因为各种原因"卡死"：

```c
// 常见死法:
while (!UART_ready);       // 串口设备没响应，死循环
while (!sensor_ok);         // 传感器坏了，永远不等不到
while (1) {}                // 代码 bug，逻辑死锁
// 电磁干扰导致 PC 寄存器跳飞 → 执行到乱码
```

一旦卡死，芯片就"僵"在那里，LED 不闪了、串口不回了——用户只能手动断电重启。

**看门狗就是自动帮你重启的"救生员"。**

---

## 3. 工作原理

```
┌─────────────────────────────────────────────────┐
│                                                  │
│  启动看门狗:                                      │
│    WDT_CONTR = 0x24;  // 1 秒后爆炸              │
│                                                  │
│        ┌──────────┐                             │
│   t=0  │ 计数器=0  │ 开始倒计时...                │
│        └────┬─────┘                             │
│             │ 程序正常运行                        │
│        ┌────▼─────┐  喂狗!                       │
│   t=0.3│ 重置计数器 │ ← WDT_CONTR = 0x34;        │
│        └────┬─────┘                             │
│             │ 程序正常运行                        │
│        ┌────▼─────┐  喂狗!                       │
│   t=0.7│ 重置计数器 │ ← WDT_CONTR = 0x34;        │
│        └────┬─────┘                             │
│             │                                    │
│        ⚠️ 程序卡死了！不喂狗了！                   │
│             │                                    │
│        ┌────▼─────┐                             │
│   t=1  │ 💥 爆炸！ │ → 芯片复位 → 重新运行        │
│        └──────────┘                             │
│                                                  │
└─────────────────────────────────────────────────┘
```

## 4. WDT_CONTR 寄存器

```
WDT_CONTR (地址 0xC1)

位:  B7          B6    B5       B4        B3        B2 B1 B0
     WDT_FLAG    -     EN_WDT   CLR_WDT   IDL_WDT   PS[2:0]
```

| 位 | 名称 | 含义 |
|-----|------|------|
| B7 | WDT_FLAG | 看门狗溢出标志（读：是否被狗咬过） |
| B5 | **EN_WDT** | **使能看门狗**（1=开） |
| B4 | **CLR_WDT** | **清看门狗/喂狗**（写 1 复位计数器） |
| B3 | IDL_WDT | 空闲模式是否停狗（1=空闲时也跑） |
| B2:B0 | PS[2:0] | **预分频**（决定溢出时间） |

---

## 5. 溢出时间设置

手册示例（@24MHz）：

| WDT_CONTR | 溢出时间 | 说明 |
|-----------|---------|------|
| `0x20` | 未使能 | EN_WDT=1但未设分频 |
| `0x23` | ~0.5s | PS=011 |
| `0x24` | **~1s** | PS=100 |
| `0x27` | ~8s | PS=111 |

公式（近似）：
```
溢出时间 ≈ (12 × 2^PS × 32768) / SYSclk

PS=100(4): 12 × 16 × 32768 / 24MHz ≈ 0.26s (但实测约 1s，手册值)
```

> 实际值建议以手册给出的为准，因为内部可能有额外的预分频。

## 6. 代码示例（来自手册）

### 6.1 启用看门狗

```c
#include "AI8051U.H"

void main()
{
    // ... 初始化 GPIO ...
    
    WDT_CONTR = 0x24;  // 使能看门狗, ~1s 溢出
    
    while (1)
    {
        // 正常任务...
        
        WDT_CONTR = 0x34;  // ⭐ 喂狗！必须在 1s 内执行
        
        Display();
        Scankey();
        MotorDriver();
    }
}
```

### 6.2 你的项目如何加看门狗

```c
void main(void)
{
    // ... GPIO 初始化 ...
    usb_init();            // USB 自动下载
    Timer0_Init();         // 定时器
    
    WDT_CONTR = 0x24;     // ⭐ 启用看门狗, 1s 超时
    EA = 1;
    
    while(1)
    {
        WDT_CONTR = 0x34; // ⭐ 喂狗！在主循环里
        
        // 你的业务代码...
    }
}
```

只要主循环正常运行，就会在 1 秒内喂狗。如果卡住了 → 不喂狗 → 1 秒后自动复位。

## 7. 喂狗的位置很重要！

```c
// ❌ 错误：在定时器中断里喂狗
void Timer0_ISR(void) interrupt 1
{
    WDT_CONTR = 0x34;  // 中断可能还在跑，但主循环已经卡死了！
}

// ✅ 正确：在主循环里喂狗
while(1)
{
    WDT_CONTR = 0x34;  // 主循环卡死 → 不喂狗 → 复位
    do_work();
}
```

---

## 8. 一次使能，终生有效

STC 的看门狗有个特性：**一旦使能，无法软件关闭！** 只有重新上电才能关闭。

```c
WDT_CONTR = 0x24;  // 启动！
// 之后无论怎么写，都关不掉了
// 只能通过断电重启来关闭
```

这样设计的好处：即使程序跑飞到恶意代码，也无法关闭看门狗。

## 9. AiCube ISP 中的设置

AiCube ISP 下载界面有个"看门狗"选项：

```
看门狗定时器: [勾选] 使能
  预分频:      [选择溢出时间]
  空闲时计数:   [勾选/不勾选]
```

可以在烧录时就配置好，代码里不需要手动写 `WDT_CONTR`。

## 10. 你现在需要吗？

| 场景 | 建议 |
|------|------|
| 闪灯测试（现在） | ❌ 不需要，万一有 bug 手动按复位就行 |
| 正式产品 | ✅ 强烈建议！产品不能死机 |
| 有 USB 通信 | ✅ USB 通信可能死锁，看门狗救命 |
| 复杂多任务 | ✅ 必须加 |

## 11. 总结

| 问题 | 答案 |
|------|------|
| WDT 是什么？ | 一个自动复位的倒计时器——不喂就炸 |
| 为什么要它？ | 程序卡死时自动重启，不需要人拔电源 |
| 怎么用？ | `WDT_CONTR = 0x24;` 开启，`= 0x34;` 喂狗 |
| 能关闭吗？ | 启动后不能软件关闭，只能断电 |
| 现在需要加吗？ | 开发阶段不需要，做产品时必须加 |
