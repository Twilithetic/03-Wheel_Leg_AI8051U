## 1. 什么是 Bootloader？

在 STC 的术语里，不叫 "Bootloader"，叫 **"系统 ISP 监控程序"**。它就是固化在芯片 ROM 中的一段**不可擦除的引导代码**。

```
┌──────────────────────────────────────────┐
│           AI8051U Flash 布局              │
│                                           │
│  ┌────────────────────────────────────┐  │
│  │   系统 ISP 监控程序 (Bootloader)     │  │
│  │   不可被用户擦除，出厂固化           │  │
│  │   地址: 芯片内部隐藏区域             │  │
│  └────────────────────────────────────┘  │
│  ┌────────────────────────────────────┐  │
│  │   用户程序区 (34KB Flash)            │  │
│  │   你的 main.c 编译后烧录到这里       │  │
│  └────────────────────────────────────┘  │
│  ┌────────────────────────────────────┐  │
│  │   IAP 数据区 (EEPROM 模拟)           │  │
│  │   可选，与用户程序区共享 Flash       │  │
│  └────────────────────────────────────┘  │
└──────────────────────────────────────────┘
```

## 2. 如何进入 Bootloader？— 上电流程

### 2.1 完整启动流程（手册第 541 页）

```
              上电复位 / 外部按键复位 /
              看门狗复位 / 低压检测复位
                        │
                        ▼
            ┌───────────────────────┐
            │  单片机运行             │
            │  系统 ISP 监控程序      │ ← ★ Bootloader 入口
            │  固定使用内部 24MHz     │
            └───────────┬───────────┘
                        │
                 是否需要进行 ISP 下载？
                   ┌──────┴──────┐
                   │              │
                   ▼ YES          ▼ NO
        ┌──────────────┐  ┌──────────────┐
        │ 下载用户程序到 │  │ 软复位到      │
        │ 用户程序区     │  │ 用户程序区     │
        │               │  │ 运行用户程序   │
        └──────┬───────┘  └──────┬───────┘
               │                  │
               ▼                  ▼
        下载完成 → 软复位      用户代码开始执行
               ↓              默认使用上次 ISP
        运行用户程序            下载时调节的 HIRC
```

### 2.2 进入 Bootloader 的条件

**硬件方式（冷启动）**：
```
1. 芯片完全断电
2. P3.2 = 0, P3.3 = 0（烧录保护引脚，仅 STC15 及以后）
3. 重新上电
4. ISP 监控程序检测到下载命令流 → 进入下载模式
```

**软件方式（热复位）**：
```c
// 通过 IAP_CONTR 寄存器软件复位到 ISP 区
IAP_CONTR = 0x60;   // SWBS=1, SWRST=1 → 软件复位到 ISP 监控程序区
```

`IAP_CONTR` 寄存器（地址 0xC7）：

| 位 | 名称 | 说明 |
|-----|------|------|
| B7 | IAPEN | IAP 使能 |
| B6 | SWBS | 软件复位选择：0=用户区，**1=ISP 区** |
| B5 | SWRST | 软件复位触发：1=产生复位 |
| B3 | SWBS2 | 软件复位选择 2 |

### 2.3 Bootloader 如何判断"是否需要下载"？

```
ISP 监控程序启动后:
  ↓
监听 UART (P3.0/P3.1) 或 USB
  ↓ 几十到几百毫秒内
检测到合法的下载命令流？
  ├── 是 → 进入下载模式，接收 HEX
  └── 否 → 直接跳转到用户程序区
```

## 3. Bootloader 里有哪些功能？

IST 监控程序提供以下功能（均在固件中实现，用户不可修改）：

| 功能 | 说明 |
|------|------|
| **握手协议** | 接收并验证下载命令流（UART 1200bps 发送 0x7F 或 USB-HID 包） |
| **芯片识别** | 返回芯片型号、Flash 大小、固件版本 |
| **擦除 Flash** | 擦除用户程序区 |
| **编程 Flash** | 将 HEX 数据写入用户程序区 |
| **校验** | 写入后回读校验 |
| **选项字节配置** | 时钟频率、复位电压、看门狗等 |
| **加密** | 支持程序加密传输 |
| **ID 号管理** | 芯片唯一 ID 读取 |
| **软复位** | 编程完成后自动复位到用户程序 |

## 4. 可以从哪里烧录？— 三种烧录接口

### 4.1 烧录接口总览

| 接口 | 引脚 | 模式 | 你的板子 |
|------|------|------|---------|
| **USB-HID** ⭐ | P3.0(D-) / P3.1(D+) | USB 直连 | ✅ 正在用！ |
| **UART** | P3.0(RXD) / P3.1(TXD) | 串口 | ❌ 需要 USB-TTL |
| **UART 切换** | P3.6/P3.7 或 P1.6/P1.7 | 串口映射 | ❌ |

### 4.2 USB-HID vs UART 对比

| | USB-HID | UART |
|------|---------|------|
| 需要额外硬件？ | ❌ 不需要 | ✅ 需要 USB-TTL |
| 需要装驱动？ | ❌ 免驱动 | ✅ CH340 等驱动 |
| 速度 | ~64KB/s | 最高 115200bps |
| 稳定性 | 🟢 好 | 🟢 好 |
| 工具 | STC-ISP (AiCube) | STC-ISP / stcgal / stcflash.py |

## 5. ⭐ 重大发现：AiCube ISP 可以自动烧录！

### 5.1 自定义命令自动复位（手册第 320-321 页）

AiCube ISP 支持**自定义下载命令**。工作原理：

```
1. 在用户程序中嵌入串口监听代码
2. 程序运行时监听串口，收到 "@STCISP#" 命令
3. 自动调用 IAP_CONTR = 0x60 跳转到 ISP 区
4. STC-ISP 自动发送命令 → 芯片自动复位 → 烧录完成 ✅
```

### 5.2 HEX 文件变化自动烧录（手册第 321 页）

**这正是你要的功能！**

> "AiCube-ISP 还可实现项目开发阶段，**完全自动下载功能**，即当下载软件侦测到目标代码被更新了，就会自动发送下载命令。要实现这个功能只需要**勾选下图中的选项**即可"

```
操作步骤:
  1. 打开 AiCube ISP
  2. 加载 HEX 文件
  3. 勾选 "当目标文件变化时自动装载并发送下载命令"
  4. 每次编译后 → ISP 自动检测到 HEX 变了 → 自动烧录！
```

### 5.3 工作流变成

```
之前:  写代码 → 编译 → 开 STC-ISP → 拖 HEX → 点下载 → 拔插 USB
之后:  写代码 → 编译 → STC-ISP 自动检测到变化 → 自动烧录 🔥
```

## 6. 实现"免断电自动下载"的完整方案

### 方案：自定义命令 + 自动检测

**Step 1**: 在 `main.c` 中嵌入自动下载代码：

```c
#include "AI8051U.h"
#include "stdio.h"

// 自定义下载命令（与 AiCube ISP 中设置的一致）
#define ISP_COMMAND "@STCISP#"

// 串口接收缓冲区
unsigned char uart_buf[16];
unsigned char uart_idx = 0;

// 定时器 0 中断 (10ms)
void Timer0_ISR(void) interrupt 1
{
    static unsigned int tick = 0;
    tick++;
    if (tick >= 100) { tick = 0; P42 = ~P42; }
}

// 串口中断 - 检测下载命令
void UART_ISR(void) interrupt 4
{
    if (RI)
    {
        RI = 0;
        uart_buf[uart_idx] = SBUF;
        uart_idx++;
        if (uart_idx >= 8)
        {
            // 检查是否收到 "@STCISP#"
            if (uart_buf[0]=='@' && uart_buf[1]=='S' && 
                uart_buf[2]=='T' && uart_buf[3]=='C' &&
                uart_buf[4]=='I' && uart_buf[5]=='S' &&
                uart_buf[6]=='P' && uart_buf[7]=='#')
            {
                // 收到命令！软件复位到 ISP 区
                IAP_CONTR = 0x60;
            }
            uart_idx = 0;
        }
    }
}

void main(void)
{
    // ... GPIO 初始化 ...
    // ... 定时器初始化 ...
    // ... 串口初始化 (2400bps 用于接收命令) ...
    
    EA = 1;
    while(1);
}
```

**Step 2**: 在 AiCube ISP 中设置：
1. 打开"收到用户命令后复位到 ISP 监控程序区"
2. 设置自定义命令为 `@STCISP#`
3. 勾选"当目标文件变化时自动装载并发送下载命令"

**Step 3**: 之后每次编译，ISP 自动干活！

## 7. 总结

| 问题 | 答案 |
|------|------|
| Bootloader 叫什么？ | **系统 ISP 监控程序**（STC 术语） |
| 它在哪？ | 芯片内部隐藏 ROM，用户不可擦除 |
| 如何进入？ | 冷启动（断电上电）或 `IAP_CONTR=0x60` 软件复位 |
| 能烧录哪些接口？ | USB-HID (P3.0/P3.1) 或 UART (P3.0/P3.1) |
| 能自动烧录吗？ | ✅ 能！AiCube ISP 有 **"HEX 变化自动烧录"** 功能 |
| 怎么做？ | 勾选"当目标文件变化时自动装载并发送下载命令" |

## 8. 附录：关键寄存器

| 寄存器 | 地址 | 作用 |
|--------|------|------|
| `IAP_CONTR` | 0xC7 | SWRST(软件复位) + SWBS(选 ISP/用户区) |
| `IAP_CMD` | 0xC5 | IAP 操作命令 |
| `IAP_TRIG` | 0xC6 | IAP 触发寄存器 |
| `IAP_TPS` | 0xF5 | IAP 编程时钟 |
