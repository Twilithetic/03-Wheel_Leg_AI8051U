`src/main.c` 是一个极简的测试程序：

```c
#include "AI8051U.h"
#include "stdio.h"

void main(void)
{
    // 配置 P0~P7 为准双向口
    P0M1=0; P0M0=0; /* P1M1~P7M1 同理 */

    // 初始化端口输出
    P0=0xFF; P1=0xFF; /* ... P7=0xFF */

    WTST = 0x00;  // 设置等待周期（CPU速度配置）

    while(1)
    {
        P42=0; Delay500ms();   // P4.2 LED 亮
        P42=1; Delay500ms();   // P4.2 LED 灭
    }
}
```

> 💡 这是一个**闪灯测试程序**，用于验证 AI8051U 芯片的最小系统是否正常工作。P4.2 引脚控制 LED 闪烁，500ms 间隔。

## 2. 问题分析

### 2.1 核心问题：AI8051U.H 与编译器的兼容性

**AI8051U.H** 是 STC 官方提供的头文件，长达 **976 行**，定义了 AI8051U 所有 SFR 寄存器和扩展 XRAM 寄存器。但它有 **三个致命问题**：

#### 问题一：无条件包含 Keil 专属头文件（🔴 阻塞当前编译）

```c
// AI8051U.H 第 6-7 行
#include "stdio.h"
#include "intrins.h"       // ❌ 无条件包含！SDCC 没有这个文件
```

- **`intrins.h`** 是 Keil C51 的专属头文件，提供 `_nop_()` 等内建函数
- SDCC 使用 `<mcs51/compiler.h>` 代替
- AI8051U.H **没有条件编译**来区分编译器 → SDCC 编译直接失败

#### 问题二：破坏性的 `main` 宏定义（🔴 致命！）

```c
// AI8051U.H 第 10-11 行
extern void _m(void);
#define main(x) main(x){_m();sprintf(0, "0");}; void _m(x)
```

这是 STC ISP 烧录器留下的"异常处理代码"，作用是在 `main()` 之前插入 `_m()` 函数调用，防止 LCALL 0x0000 异常。但这会导致：

1. **`main` 被宏替换** → 用户写的 `void main(void)` 被展开为 `void main(void){_m();sprintf(0,"0");}; void _m(void)`
2. **语义完全破坏** → `sprintf(0, "0")` 向地址 0 写入字符串，这是危险操作
3. **即使编译通过**，运行时行为也不可预测

#### 问题三：SFR 声明语法不通用（🟡 影响范围）

```c
// AI8051U.H 使用 Keil 语法
sfr  P0     = 0x80;    // Keil 语法
sbit P00    = P0^0;    // Keil 位寻址语法
```

| 特性 | Keil C51 语法 | SDCC 语法 |
|------|--------------|-----------|
| SFR 声明 | `sfr P0 = 0x80;` | `__sfr __at(0x80) P0;` |
| 位声明 | `sbit P00 = P0^0;` | `__sbit __at(0x90) P00;` |
| 16位 SFR | `sfr16 T2 = 0xCC;` | `__sfr16 __at(0xCCCC) T2;` |

但 `sfr`/`sbit` 作为关键字，**Keil C51 和 SDCC 都能识别**（只是内部实现不同），所以这个问题比前两个**轻微**。

### 2.2 编译器历史演进

| 阶段 | 编译器 | 结果 | 原因 |
|------|--------|------|------|
| **阶段 1** | Keil C51 | ❌ **191 个错误** | `AI8051U.H` 扩展 SFR 地址超出标准范围（`ERROR C146: invalid base address`） |
| **阶段 2** | SDCC（当前） | ❌ **1 个致命错误** | `intrins.h` 不存在 |

### 2.3 为什么建议 SDCC

1. **错误更少**：1 个 vs 191 个，且只有 1 个根本原因
2. **免费开源**：无需购买 Keil License
3. **EIDE 原生支持**：EIDE 内置 SDCC 配置模型
4. **AI8051U.H 的设计倾向**：STC 官方头文件使用了 SDCC 风格的 `__sdcc` 相关语法
5. **提供转换工具**：SDCC 社区有 `keil2sdcc.pl` 脚本可以转换头文件

## 4. 解决方案对照表

| 方案 | 做法 | 优点 | 缺点 | 难度 | 推荐度 |
|------|------|------|------|------|--------|
| **A: 修复 AI8051U.H** | 添加 SDCC 条件编译，移除 main 宏 | 彻底解决；一次修复永久使用 | ⚠️ 修改官方文件有风险 | ⭐⭐ | ⭐⭐⭐ |
| **B: 新建兼容头文件** | 复制 AI8051U.H → 修改为 SDCC 兼容版本 | 不修改官方文件；可维护 | 需要同步更新 | ⭐⭐⭐ | ⭐⭐⭐⭐ |
| **C: 用 reg52.h 简化开发** | 只用 standard SFR + 手动定义扩展 SFR | 极简；无依赖 | 无法使用 AI8051U 特有功能 | ⭐ | ⭐⭐ |
| **D: 切回 Keil C51** | 获取 Keil C51 兼容头文件 | 传统方案 | 需要付费 License；191个错误还未解决 | ⭐⭐⭐⭐⭐ | ⭐ |

### 方案 B 详解（⭐ 推荐）

1. 创建 `src/STC/AI8051U_SDCC.h`（保留原文件）
2. 添加 SDCC 条件编译：
   ```c
   #ifdef __SDCC__
       #include <mcs51/compiler.h>
       #define _nop_() __asm nop __endasm
   #else
       #include "intrins.h"
   #endif
   ```
3. 注释掉第 11 行的 `#define main(x)` 宏
4. `main.c` 改为 `#include "AI8051U_SDCC.h"`
