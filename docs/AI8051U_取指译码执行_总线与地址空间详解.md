# AI8051U 取指 → 译码 → 执行：总线与地址空间详解

> 姐姐帮宝宝整理的 CPU 底层原理笔记 💖  
> 记录了复位后第一条指令的读取路径，以及取指/译码/执行三阶段中涉及的所有总线和地址空间

---

## 一、快速回顾：AI8051U 是什么核心？

```
AI8051U = Intel MCS-251 (80251) 架构的 STC 实现
        = 32 位 ALU + 32 位寄存器 + 24 位地址总线
        = 兼容传统 8 位 8051 指令集的 32 位单片机
```

## 三、三条地址空间 ⭐

AI8051U（基于 80251）有**三个完全独立的地址空间**，各有自己的总线：

### 3.1 Memory Space（内存空间）— 16MB

```
地址范围: FF:0000h ~ FF:FFFFh (24 位地址)
存放内容: ① 程序代码 (Flash)  ② 数据 (XDATA RAM)  ③ XFR 扩展寄存器

AI8051U 实际使用:
  Flash:   FF:0000h ~ FF:FFFFh (64KB — 虽然地址空间是 16MB，但芯片集成了 64KB Flash)
  XDATA:   片内扩展 RAM
  XFR:     0x7E:0000 ~ 0x7E:FFFF (需要 EAXFR=1 才能访问！)

访问方式:
  取指令:    自动通过 PC + I-Bus
  读数据:    MOVX A, @DPTR (DPTR+DPX 拼出 24 位地址)
  写数据:    MOVX @DPTR, A

速度控制:  取指→WTST  数据→CKCON
```

### 3.2 SFR Space（特殊功能寄存器空间）— 512B

```
地址范围: S:000h ~ S:1FFh (9 位地址，0x80~0xFF 是最常用的高 128 字节)
存放内容: 外设控制寄存器 (P0, P1, ACC, PSW, IE, TMOD, ...)

访问方式:
  直接寻址:  MOV P0, #0x55     (地址在 opcode 里)
  SFR 名:    MOV 0x80, #0x55   (等价写法)

特点:
  ✅ 永远可访问，不需要任何使能
  ✅ 有自己的独立总线 (SFR Bus)，不和 Memory Space 冲突
  ❌ SFR Space 的地址 S:80h 和 Memory Space 的地址 FF:0080h 是完全不同的东西！
```

### 3.3 Register File（寄存器文件）— 64B (CPU 内部)

```
存放内容: CPU 的通用寄存器

传统 8051 寄存器:
  R0 ~ R7   (8 位 × 8 个)       位于 Register File 低 32 字节

80251 扩展寄存器 (32 位模式):
  DR0 ~ DR3  (与 R0~R7 重叠)
  DR4 ~ DR59 (32 位 × 56 个)     新增的高性能寄存器
  WR0 ~ WR30 (16 位 × 16 个)     字寄存器，与 DR 重叠

特点:
  ✅ 完全在 CPU 核心内部，通过 SRC/DST 内部总线访问
  ✅ 零等待，最快！
  ❌ 不可从 Memory Space 或 SFR Space 访问
```

> 📖 **Intel TSC80251 编程指南 §3.1 (Page 17)**：
> *"TSC80251 microcontrollers have three address spaces: a memory space, a Special Function Register (SFR) space and a register file."*

## 四、五条内部总线 ⭐

### 4.1 I-Bus（指令总线）— 16 位宽 🔵

```
宽度:   16 bit (每周期可取 2 字节)
方向:   Flash → CPU (只读)
连接:   Flash 控制器 → CPU 指令寄存器 (IR)
用途:   取指令 (Fetch 阶段)
控制:   WTST 寄存器 (0xE9) 设定等待周期

类比:   📖 菜谱传送带 — 把菜谱从书架快速送进厨师眼里
```

> 📖 **Intel MCS-251 Architecture Overview** (PDF 27262001)：
> *"The MCS 251 architecture has an internal 16-bit wide instruction bus capable of sustained 2 bytes/state code fetches."*

### 4.2 Memory Data Bus（内存数据总线）— 8 位宽 🟢

```
宽度:   8 bit
方向:   双向 (CPU ↔ XDATA/XFR)
连接:   CPU ↔ XDATA RAM / XFR 扩展空间
用途:   MOVX 指令的数据读写 (Execute 阶段)
控制:   CKCON 寄存器 (0xEA) 设定等待周期
        EAXFR 位 (P_SW2.7) 控制是否允许访问 XFR 空间

类比:   🛒 买菜小车 — 从仓库 (XDATA) 取食材或存放成品
```

> 📖 **Intel MCS-251 Architecture Overview**：
> *"It also has an 8-bit data bus capable of one byte/state data transfer rate."*

### 4.3 SFR Bus（特殊功能寄存器总线）— 8 位宽 🟡

```
宽度:   8 bit
方向:   双向 (CPU ↔ SFR)
连接:   CPU ↔ SFR Space 中的外设寄存器
用途:   读写外设控制寄存器 (Execute 阶段)
        MOV P0, A / MOV A, PSW / SETB EA 等

特点:   不需要 CKCON/WTST 控制（总是最快速度）
        不需要 EAXFR 使能（标准 SFR 永远可访问）

类比:   🎛️ 控制面板排线 — 厨师直接操作灶台旋钮 (不需要去仓库)
```

### 4.4 SRC Bus（源操作数总线）— 8 位宽 🟣

```
宽度:   8 bit
方向:   Register File → ALU / Decoder (只读)
连接:   Register File → 指令译码器 + ALU 输入
用途:   译码阶段读取操作数、执行阶段读取 ALU 源操作数

类比:   🧠 神经元输入 — 从记忆区提取"要算什么"
```

> 📖 **Intel 8XC251SA Block Diagram**：CPU 框图中标有 `SRC1 (8)` 和 `DST (16)` 总线

### 4.5 DST Bus（目标操作数总线）— 16 位宽 🔴

```
宽度:   16 bit
方向:   ALU → Register File (只写)
连接:   ALU 输出 → Register File 写端口
用途:   执行阶段写回运算结果

类比:   🧠 神经元输出 — 把"算完了的结果"存回记忆区
```

> 📖 **Intel 8XC251SA Block Diagram**：`DST (16)` 总线，比 SRC 宽是因为要支持 16/32 位写回

### 4.6 五条总线汇总

| 总线 | 宽度 | 方向 | 用在哪阶段 | 控制寄存器 |
|------|:---:|------|:---:|------|
| **I-Bus** | 16 bit | Flash→CPU | **Fetch** | WTST (0xE9) |
| **Memory Data Bus** | 8 bit | 双向 | **Execute** | CKCON (0xEA) |
| **SFR Bus** | 8 bit | 双向 | **Execute** | 无 (总是最快) |
| **SRC Bus** | 8 bit | RF→CPU | **Decode+Execute** | 无 (CPU内部) |
| **DST Bus** | 16 bit | CPU→RF | **Execute** | 无 (CPU内部) |

## 五、复位后：第一条指令怎么读？

```
上电复位 →
  PC = FF:0000h                 ← 硬件自动设定的复位向量
    │
    ▼
  CPU 把 PC 值送上 24 位地址总线
    │
    ▼
  Flash 控制器收到 FF:0000h
    │  (等待 WTST 指定的周期数，默认 WTST=1 → 等 1 拍)
    ▼
  Flash 存储阵列输出 opcode 字节
    │
    ▼
  通过 16-bit I-Bus 送入 CPU 指令寄存器 (IR)
    │  (虽然 I-Bus 是 16 位宽，但复位后第一条只取 1 个指令字节)
    ▼
  IR 里的 opcode 进入译码阶段...
```

复位后 CPU 状态速查：

| 寄存器 | 复位值 | 含义 |
|--------|:------:|------|
| **PC** | **FF:0000h** | 程序计数器 |
| WTST | 1 | Flash 访问等 1 拍 |
| CKCON | 0000x000B | XDATA 访问默认速度 |
| EAXFR | 0 | XFR 空间锁死 🔒 |
| EA | 0 | 全局中断关闭 |

## 六、三阶段总线活动拆解

### 6.1 Fetch（取指）阶段

```
   PC ──24bit 地址──► Flash 控制器 ──► Flash 阵列
                                        │
                              (等 WTST 拍数)
                                        │
                              ──16bit I-Bus──► 指令寄存器 (IR)

涉及的总线:     ✅ 24-bit 地址总线 (CPU→Flash)
               ✅ 16-bit I-Bus (Flash→CPU)

涉及的地址空间:  ✅ Memory Space (代码区)
               ❌ SFR Space
               ❌ Register File

速度控制:       WTST (0xE9)
               AccessCodeFastest() → WTST=0
```

### 6.2 Decode（译码）阶段

```
   指令寄存器 (IR) ──► 指令译码器 (Decoder)
                          │
              ┌───────────┼───────────┐
              ▼           ▼           ▼
        识别 opcode   确定寻址方式   读源操作数
        (ADD?MOV?)   (寄存器/直接)  ──► SRC Bus (8bit) ──► Register File

涉及的总线:     ✅ SRC Bus (8bit, Register File → Decoder)
               ❌ I-Bus (除非需要取额外操作数字节)
               ❌ Memory Data Bus
               ❌ SFR Bus

涉及的地址空间:  ✅ Register File
               ❌ Memory Space
               ❌ SFR Space

额外取操作数:   如果指令超过 1 字节 (比如 MOV P0, #data 是 3 字节)，
               译码器会触发额外的 Fetch 周期去取操作数字节。
               这些额外的取指也走 I-Bus + Memory Space。
```

### 6.3 Execute（执行）阶段

这是最复杂的阶段，**不同指令涉及不同总线组合**：

#### A. 纯寄存器操作（最快 ⚡）

```
例: ADD A, R0   /   MOV DR4, DR8   /   INC DPTR

  SRC Bus (8bit) → ALU 输入 (A 和 R0)
  ALU 运算
  DST Bus (16bit) → Register File 写回结果

涉及: 只有 SRC + DST Bus ✅  (其余全部 ❌)
耗时: ~1 周期
```

#### B. SFR 访问

```
例: MOV P0, #0x55   /   SETB EA

  CPU → SFR Bus (8bit 地址 S:80h) → P0 寄存器
  CPU → SFR Bus (8bit 数据 0x55)   → 写入 P0

涉及: SFR Bus ✅  +  Register File ✅
     其余 ❌
耗时: ~1~2 周期
```

#### C. 内存/数据访问

```
例: MOVX @DPTR, A   (写 A 到 XDATA)

  DPTR+DPX → 24bit 地址 → Memory Space
  A 的值 → Memory Data Bus (8bit) → XDATA RAM

涉及: Memory Data Bus ✅  +  24bit 地址总线 ✅
     SRC/DST Bus ✅ (读 A 的值)
     其余 ❌
耗时: ~2+ 周期 (取决于 CKCON)
```

#### D. XFR 扩展空间访问

```
例: 读 USB 寄存器 (地址 0x7E:FE00)

  前提: EAXFR = 1  ← 必须先开门！否则读写被硬件忽略！
  
  DPTR = 0xFE00, DPX = 0x7E  → 24bit 地址 = 0x7E:FE00
  → Memory Data Bus (8bit)    → XFR 空间寄存器

涉及: 和 C 完全相同 (Memory Data Bus + 地址总线)
     但地址指向 0x7E:xxxx (XFR 空间)
```

### 6.4 四种执行路径对比

| 指令类型 | I-Bus | Memory Bus | SFR Bus | SRC/DST Bus | 典型周期 |
|---------|:---:|:---:|:---:|:---:|:---:|
| 寄存器运算 (ADD A,R0) | ❌ | ❌ | ❌ | ✅ | 1 |
| SFR 读写 (MOV P0,A) | ❌ | ❌ | ✅ | ✅ | 1~2 |
| 内存读写 (MOVX @DPTR,A) | ❌ | ✅ | ❌ | ✅ | 2~N |
| XFR 读写 (写 USB 寄存器) | ❌ | ✅ | ❌ | ✅ | 2~N |

## 七、完整指令追踪：`MOV P0, #0x55`

让姐姐用一条具体指令，一步步走完三阶段：

```
指令: MOV P0, #0x55
机器码: 75 80 55  (3 字节)
        │  │  └── 立即数: 0x55
        │  └───── 目标地址: S:80h (P0 寄存器)
        └──────── opcode: MOV direct, #immediate

═══════════════════════════════════════════════
① FETCH — 取 opcode 字节
═══════════════════════════════════════════════
  PC = FF:0100h ──24bit 地址──► Flash
  Flash ──I-Bus (16bit)──► CPU: 得到 0x75
  PC = PC + 1 → FF:0101h

═══════════════════════════════════════════════
② DECODE + 额外取操作数
═══════════════════════════════════════════════
  译码器分析 opcode=0x75:
    → 这是 3 字节指令: MOV direct, #immediate
    → 还需要读 2 个字节！

  触发 Fetch: PC=FF:0101h → Flash → I-Bus → 0x80 (目标地址)
  触发 Fetch: PC=FF:0102h → Flash → I-Bus → 0x55 (立即数)
  PC = FF:0103h (指向下一条指令)

  译码器确定:
    目标 = SFR 地址 S:80h (P0)
    源数据 = 立即数 0x55 (暂存到 Register File)

═══════════════════════════════════════════════
③ EXECUTE — 写入 P0
═══════════════════════════════════════════════
  CPU ──SFR Bus (地址 S:80h)──► P0 端口寄存器
  CPU ──SFR Bus (数据 0x55)────► 写入！

  内部:
    SRC Bus: 从 Register File 读取 0x55
    (ALU 直通，不做运算)
    DST Bus: 不涉及 (目标在 SFR 空间)

═══════════════════════════════════════════════
涉及的总线统计:
  I-Bus:      3 次 (取 0x75, 0x80, 0x55)
  SFR Bus:    1 次 (写 S:80h)
  SRC Bus:    1 次 (读立即数 0x55)
  DST Bus:    0 次
  Memory Bus: 0 次
═══════════════════════════════════════════════
```

## 八、总线 × 地址空间对照表（核心速查！）

```
                     Memory Space        SFR Space          Register File
                    ───────────────     ──────────         ──────────────
 存放什么？         代码 + 数据          外设控制寄存器        CPU 通用寄存器
 大小               16MB (AI8051U:64K)  512B (256B常用)      64B (40B有效)
 地址宽度           24 bit              9 bit               CPU 内部
 例                 FF:0000h            S:80h (P0)           R0 / DR4
 ───────────────────────────────────────────────────────────────────
 
 ① FETCH 取指 ──►   ✅ I-Bus            ❌                  ❌
                    16-bit 指令总线
                    (Word 取指)

 ② DECODE 译码 ──►  ❌                  ❌                  ✅ SRC Bus
                                                           (读寄存器操作数)

 ③ EXECUTE 执行:
   寄存器运算 ────►   ❌                  ❌                  ✅ SRC+DST Bus

                    CKCON (数据)
```

## 九、速度控制寄存器速查

### 9.1 WTST — 取指速度

```c
sfr WTST = 0xe9;               // 标准 SFR，不需要 EAXFR
#define AccessCodeFastest()  AccessCodeSpeed(0)  // WTST=0
```

| WTST 值 | 效果 | 适用 SYSCLK |
|:---:|------|:---:|
| 0 | 零等待，每周期取指 ⚡ | ≤40MHz |
| 1 | 等 1 拍（默认） | ~50MHz |
| 2 | 等 2 拍 | >50MHz |

### 9.2 CKCON — 数据访问速度

```c
sfr CKCON = 0xea;              // 标准 SFR，不需要 EAXFR
#define AccessIXramFastest()  (CKCON = 0)
```

| CKCON[2:0] | XDATA 等待周期 |
|:---:|:---:|
| 0 | 零等待 ⚡ |
| 1~7 | 等待 1~7 个额外周期 |

### 9.3 EAXFR — XFR 空间门锁

```c
sfr  P_SW2 = 0xba;             // 标准 SFR
sbit EAXFR = P_SW2 ^ 7;        // bit7
#define EnableAccessXFR()  SET_REG_BIT(P_SW2, EAXFR_MSK)
                                // P_SW2 |= 0x80
```

| EAXFR | 效果 |
|:---:|------|
| 0 (默认) | 🔒 XFR 空间锁死，写入无效 |
| 1 | 🔑 XFR 空间可正常读写 |

## 十、关键结论

```
┌─────────────────────────────────────────────────────────┐
│                                                         │
│  ① 取指:   PC → 24bit 地址 → Flash → I-Bus(16bit) → CPU │
│            → 只用 Memory Space + I-Bus                  │
│                                                         │
│  ② 译码:   指令译码器 → SRC Bus(8bit) → Register File    │
│            → 只在 CPU 内部，不碰外部总线                    │
│                                                         │
│  ③ 执行:   不同指令 = 不同总线组合                         │
│    寄存器:  只用 SRC/DST Bus (最快！)                     │
│    SFR:     + SFR Bus                                   │
│    内存:    + Memory Data Bus (8bit, CKCON 控速)         │
│    XFR:    + Memory Data Bus (需 EAXFR=1 开门)           │
│                                                         │
│  ④ 三种空间各有独立总线，互不干扰                          │
│  ⑤ AI8051U 虽然兼容 8 位 8051 指令，                      │
│     但内部是 32 位 ALU + 24 位地址 + 16 位取指总线        │
│                                                         │
└─────────────────────────────────────────────────────────┘
```
